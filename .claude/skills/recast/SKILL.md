# recast

## 무엇을 하나

재구조화는 원문의 지식을 다시 짜서, 읽고 나면 원문을 다시 볼 필요 없는 한국어 글로 만드는 일이다. 번역도 요약도 아니다. 실제 집필은 `uv run "${CLAUDE_SKILL_DIR}/scripts/cli.py" run`이 원문마다 띄우는 깨끗한 헤드리스 세션이 한다 — 원문 사본 하나만 보고, CLAUDE.md·스킬·훅 없이, 같은 모델과 같은 지시문(`scripts/recast/system_prompt.md`)으로 원문 전체를 읽고 한 번에 쓴다. 그래서 집필을 직접 하거나 다른 모델·서브에이전트에 넘기지 않는다: 이 세션의 위임 기본값과 상관없이 모든 파일이 같은 조건으로 쓰여야 결과를 믿을 수 있다. 원문과 출력 본문도 읽지 않는다 — 여러 파일의 본문이 이 컨텍스트에 쌓이면 조율할 자리가 사라진다. 모델·effort는 CLI 기본값을 쓰고, 사용자가 정할 때만 바꾼다. 인자, 출력, 실패 종류는 `--help`가 설명한다.

## 실행

`run`은 파일 수에 비례해 오래 걸리는 블로킹 명령이다. Bash의 `run_in_background`로 돌리고 완료 알림을 기다린다. 사용자가 경로 뒤에 덧붙인 말은 `--instructions`로 넘긴다. `--force`는 이미 있는 `Recast_`를 덮어 되돌릴 수 없으므로 사용자가 다시 쓰라고 했을 때만 붙인다.

사용자가 진행이나 멈춤 여부를 물으면 `status`를 본다. 신호가 오래 끊긴 워커는 CLI가 스스로 끝내므로(기준은 `--help`), 판단할 것은 신호는 오는데 진척이 없는 경우다 — 단계에 머문 시간(`phase_seconds`)이 원문 길이에 비해 지나치게 길거나, `쓰는 중`인데 `written_chars`가 늘지 않거나, `속도 제한 대기`만 이어진다. 그렇게 보이면 근거와 함께 알리고 멈출지 묻는다. 멈추려면 그 백그라운드 작업을 멈춘다. 다시 실행할 때는 `--force` 없이 돌리면 끝난 파일은 건너뛴다. `--force`로 돌던 실행을 이어 갈 때는 실패하거나 중단된 원문만 경로로 준다 — 같은 명령을 그대로 다시 돌리면 이미 끝낸 출력까지 다시 덮는다.

## 결과를 전하기

요약과 파일별 결과를 전하고, 실패에는 `reason`과 `next`를 붙인다. `worker_said`는 워커의 마지막 답이다. 출력이 없는 실패에서는 그 원문을 왜 쓰지 않았는지 말하고, 성공에서는 원문이 깨져 버린 대목을 말한다 — 둘 다 워커가 직접 확인한 결손이므로 전한다('버린 대목 없음'은 전하지 않아도 된다). 결과가 보여 주지 않는 것도 말한다: 충실도는 아무도 자동으로 검사하지 않았고, 글자 수 비율은 그 척도가 아니다(포장이 많은 대담은 크게 줄고, 밀도 높은 글은 거의 줄지 않는다). 사용자가 품질을 물을 때만 원문과 출력의 해당 대목을 함께 읽는다. 출력이 왜 그렇게 쓰였는지 묻거나 원칙을 바꾸려 하면 `scripts/recast/system_prompt.md`를 연다.
